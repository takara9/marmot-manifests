# Marmot で Ceph を動かしてみよう — シングルノード構成

**1台のサーバーから、分散ストレージ Ceph の世界を体験してみませんか？**

Marmot を使って Ceph 環境を構築し、Web Dashboard で状態を確認したり、クライアントからストレージにアクセスしたりするための実験用マニフェストです。

複雑な構築作業をひとつずつ手作業で進める代わりに、Marmot のマニフェストを使って環境構築を体験できます。

この手順を通して、Marmot によるインフラ構築と Ceph の基本的な操作を学びましょう。

> **用途：学習・実験・動作検証**
>
> シングルノード構成は、ノード障害に対する冗長性を提供しません。本番環境や重要なデータの保存先としてではなく、検証環境として利用してください。

## このマニフェストで体験できること

- Marmot のマニフェストを使った Ceph 環境の構築
- Ceph Dashboard によるストレージ環境の確認
- Ceph クライアントからのストレージへのアクセス
- Marmot と Ceph を組み合わせたプライベートクラウドの実験

## 1. 構築の流れ

```text
Linux サーバー
      |
      v
    Marmot
      |
      | single-ceph.yaml
      v
  Ceph 環境の構築
      |
      +----> Ceph Dashboard
      |
      +----> Ceph クライアントからのアクセス
```

## 2. 事前に準備するもの

実行する前に、次の項目を確認してください。

- Marmot がインストールされ、`mactl` から操作できること
- `mactl` で対象の Marmot 環境に接続できること
- マニフェストが要求する CPU、メモリ、ディスク容量を確保できること
- Ceph の Dashboard やクライアントが利用するネットワークにアクセスできること
- 検証に使用してよいサーバーとストレージを用意していること

**注意：** 必要な CPU、メモリ、ディスク容量、ネットワーク設定は `single-ceph.yaml` の内容に依存します。実行前にマニフェストを確認してください。

## 3. Ceph 環境を構築する

このディレクトリにあるマニフェストと Ansibleプレイブックを使って構築を開始します。

```bash
mactl create -f single-ceph.yaml
```

構築処理が完了するまで待ちます。Ceph の構成要素の起動や初期化には時間がかかる場合があります。

Ansibleプレイブックからの出力に、CephのコンソールのURLアドレス、パスワードが表示されます。

```console
$ mactl create -f single-ceph.yaml 

＜中略＞
Ceph Dashboard is now available at:

	     URL: https://ceph-single:8443/
	    User: admin
	Password: u5o1d2bkfk
```


作成されたリソースや状態は、Marmot のコマンドで確認してください。

```bash
mactl get
```

※ 利用する Marmot のバージョンやリソースの種類によって、確認コマンドを適宜指定してください。


## 4. Ceph Dashboard にアクセスする

構築が完了したら、マニフェストや構築時の出力で案内された Dashboard の URL を確認し、ブラウザーで開きます。

Dashboard では、Ceph クラスターの状態やストレージ関連の情報を確認できます。

- **URL：** 構築環境で案内された URL
- **ユーザー名：** 構築時に設定・生成された管理者アカウント
- **パスワード：** 構築時に設定・生成された認証情報

認証情報は公開リポジトリに固定値として記載せず、安全な方法で取得してください。

自己署名証明書を使用している場合、ブラウザーに証明書の警告が表示されることがあります。接続先と証明書を確認したうえで対応してください。

## 5. クライアントからストレージを利用する

Ceph 環境を構築したら、クライアントからストレージにアクセスする実験を行います。

CephFS を利用する場合は、まず次の点を確認してください。

- クライアントに必要な Ceph クライアントツールがインストールされていること
- 接続先のアドレスとポートが正しいこと
- Ceph の設定ファイルと認証情報が適切に配置されていること
- クライアントに必要な権限が付与されていること

接続コマンドは、実際に構築された環境のアドレス、ファイルシステム名、認証方式に合わせて設定してください。

認証情報をコマンドラインに直接記述すると、シェル履歴などに残る可能性があります。検証用の認証情報であっても、安全な管理方法を使用してください。

## 6. うまく動かないときは

次の項目を順番に確認してください。

1. Marmot の操作対象に接続できているか
2. マニフェストの内容に誤りがないか
3. 必要な CPU、メモリ、ディスク容量が確保されているか
4. Ceph の構成要素が起動し、正常な状態になっているか
5. Dashboard の名前解決、IP アドレス、ポートに問題がないか
6. クライアントの設定ファイルと認証情報が正しいか

問題が解決しない場合は、実行したコマンド、エラーメッセージ、関連するリソースの状態を確認してください。秘密情報や認証トークンは、公開 Issue に貼り付けないでください。

## 7. 後片付け

検証が終わったら、作成したリソースを削除します。

削除前に、必要なデータが残っていないことを確認してください。

```bash
# 実際のリソース名と依存関係を確認してから削除する
mactl get
```

Ceph のストレージや関連リソースの削除は、マニフェストで作成したリソースと依存関係を確認し、実際の環境に合った手順で行ってください。

## 8. 次に試してみよう

Ceph が動作したら、次の実験にも挑戦してみてください。

- Ceph の状態や容量を Dashboard で観察する
- クライアントからデータを読み書きする
- Marmot で管理する仮想マシンとストレージを組み合わせる
- 複数ノード構成の Ceph と比較し、可用性や冗長性の違いを学ぶ

## Marmot について

Marmot は、YAML ベースの宣言的な操作で仮想マシン、ネットワーク、ストレージを管理するプライベートクラウド基盤です。

このマニフェスト集では、実際に手を動かしながら Marmot の機能を学べる環境を提供しています。

- **Marmot 本体：** https://github.com/takara9/marmot
- **マニフェスト集：** https://github.com/takara9/marmot-manifests

ぜひ実際に動かしてみて、気づいたことや改善案を共有してください。
